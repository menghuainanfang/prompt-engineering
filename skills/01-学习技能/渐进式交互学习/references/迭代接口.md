# 未来迭代接口

> 本文件预留了本技能未来可能的进化方向。当条件成熟时，这些接口可以直接接入现有工作流，
> 无需大规模重构。从主 SKILL.md 外置于此（2026-08-16 精简）。

## 接口 1：Obsidian 知识节点可视化

**问题**：用户在 Obsidian 中用 `[[]]` wikilink 和 Canvas/Excalidraw 管理知识图谱。
本技能生成的笔记当前只有文字版的逻辑链，没有与 Obsidian 的可视化层打通。

**预留接入点**：
- 笔记 frontmatter 中的 `completed_sections`、`prerequisite_detours`、`next_session_target` 字段
- 如果未来「生成思维导图与知识图谱」技能支持从 frontmatter 自动生成 Canvas 节点图：
  - 已完成节 → 点亮节点 ✅
  - 节间逻辑连接（← 承接 / → 铺垫）→ 自动生成 Canvas 边
  - 前置补课记录 → 生成子节点和依赖边
- 阶段2 子阶段 2e（逻辑连接）输出的 `← 承接 / → 铺垫` 信息 → Canvas 的有向边数据源

**触发迭代的信号**：
- 「生成思维导图与知识图谱」技能支持了从 frontmatter 自动生成节点图
- 用户在笔记目录中积累了多份本技能的笔记，需要全局可视化学习路径

## 接口 2：跨材料学习路径管理

**问题**：用户可能按一个学习路径连续学多份材料（教材第1章 → 论文A → 教材第2章 → 论文B）。
当前每份材料独立生成笔记，学习路径只存在于断点续学机制的 `跨材料学习路径` 一节。

**预留接入点**：
- 笔记 frontmatter 中的 `discipline`、`difficulty`、`tags` 字段——可用于自动匹配相关材料
- 阶段3.4（边界与未解决问题）中用户指出的「后续学习方向」
- `next_session_target` 可以跨材料指向另一个笔记文件
- 如果未来有一个「学习路径管理器」：
  - 读取多份笔记的 frontmatter
  - 生成课程大纲式的学习路线图
  - 推荐学习顺序（按依赖关系和难度递进）

**触发迭代的信号**：
- 用户的笔记目录中有了 ≥5 份本技能生成的学习笔记
- 用户表达了「不知道接下来该学什么」的需求
- 多份笔记之间存在明确的前置依赖关系

## 接口 3：前置知识诊断的精准化

**问题**：当前阶段1 的诊断依赖 AI 对用户回答的主观判断（✅/⚠️/❌）。
未来可以引入更结构化的诊断方式。

**预留接入点**：
- 阶段1.2 的「诊断问题设计原则」可以扩展为**结构化诊断题库**：
  - 常见前置知识的标准化诊断问题（如"矩阵乘法"的诊断问题固定为 3 道递进题）
  - 每个诊断问题对应 3 个典型的回答模式（✅/⚠️/❌），减少主观判断
- 诊断结果可以量化为 `prerequisite_score`（0-100），存入笔记 frontmatter
- 如果未来有「知识诊断」独立技能，本技能的阶段1 可以委托给它

**触发迭代的信号**：
- AI 对同一前置知识的诊断标准在不同会话中不一致
- 用户反馈诊断问题太简单/太难
- 积累了 ≥10 次诊断会话的经验数据

## 接口 4：材料类型的更细粒度适配

**问题**：当前支持 5 种材料类型（论文/教科书章节/技术文档/书籍/讲义），但类型内部的差异也很大——
一篇 4 页的 short paper 和一篇 30 页的 review paper，拆解方式应该不同。

**预留接入点**：
- 阶段0.2（全局扫描）的「材料类型」可以从枚举扩展为**带子类型的分类**：
  - 论文 → 理论论文 / 实验论文 / 综述 / 短论文 (short paper) / 博士论文章节
  - 书籍 → 教科书 / 专著 / 科普书 / 手册
- 阶段2 的逐节节奏可以根据子类型自适应：
  - 综述论文：每节可以更快（重点在建立领域地图，不在技术细节）
  - 理论论文：每节可以更慢（重点在推导的每一步）
  - 实验论文：实验部分走特殊的「假设→设计→结果→解读」子节奏

**触发迭代的信号**：
- 用户用本技能读了 ≥3 种不同类型的材料
- 用户反馈某种类型的材料的节奏不合适

## 接口 5：协作学习模式

**问题**：当前是一对一（AI + 单个学习者）。未来可能需要支持一对多场景——
比如学习小组一起读一篇论文，或教师用本技能备课。

**预留接入点**：
- 阶段2 的引导问题（2b）和检验问题（2d）可以标记 `discussion_seed: true`，表示「这个问题适合小组讨论」
- 笔记可以导出为「讨论大纲」格式（含讨论问题、关键争议点、小组练习）
- 阶段3（全局逻辑重建）的「用户先讲」可以扩展为「小组先讨论，然后各组代表讲」

**触发迭代的信号**：
- 用户在学习过程中提到「和同学一起」「小组」「课堂」等场景

## 接口 6：笔记与笔记技能体系的深度整合

**问题**：递归补课可能导致知识域的实际变化（线性代数 → 初等代数），而当前本技能的笔记使用固定的 `discipline` 标签。

**预留接入点**：
- 笔记 frontmatter 中的 `discipline` 可以在递归补课时**动态调整**：
  - 如果补课内容跨越了学科边界（如从数理降维到更基础的数理），`discipline` 不变但 `difficulty` 不适用
  - 新增 `actual_domain` 字段记录「实际覆盖的知识域」，与 `discipline`（预期知识域）区分
- 笔记中的「前置补课记录」可以自动触发「补全笔记逻辑链」的领域重分类
- `tags` 字段可以按递归补课的实际内容动态添加标签

**触发迭代的信号**：
- 一次学习会话中触发了 ≥2 层递归
- 用户反馈笔记的标签/分类与实际学习内容不符
- 「补全笔记逻辑链」技能支持了领域感知的标签推荐
