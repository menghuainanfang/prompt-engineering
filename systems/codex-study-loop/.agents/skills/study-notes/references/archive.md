# 学习档案协议

## 环境与保存能力
技能被读取不代表具有本地文件访问能力。先按当前工具区分：聊天上下文、可读取的附件、可写的文件或已连接文档。路径仅在具有对应文件工具的环境解析。
当前环境无法访问本地统一库时，聊天教学和使用已提供材料继续进行，不反复要求检查本地目录。需要归档到该库时保留待写内容与准确断点，交给具有本地访问能力的环境；未写入不称已归档。用户明确选择云端文档或下载文件时采用该目标，不宣称同步回本地原档案。
同一会话已选择 realtime 但写入工具不可用时，明确本轮未保存，保留待补记录；不能悄悄改成已保存或新建备用主档案。

## 定位与命名
学习文件统一库的位置来自用户的工作区说明、当前会话或明确指定。生成、整理、归档或更新任何学习相关文件（地图、笔记、练习、评估、论文学习材料及学习可视化等）时，先访问并查找该库，最终文件统一保存于该库或其适当子目录；用户当次明确指定其他位置时遵从当次指令。尚未配置时仍可聊天学习，真正需要归档时再用一个简短问题确认路径。此位置约定不触发原本无需生成文件的聊天教学，也不要求搬动教材原件。
旧路径失效或用户移动文件后，不宣称实时跟踪。下一次实际读写时，先在统一库按文件名、课程、节点 ID 和正文内容查找并核对原档案，确认后使用新位置并在本次授权更新范围内修正相关路径引用；保留原内容和学习证据，不因路径变化重新生成或创建副本。若出现多个候选且无法判断，以简短问题确认；未找到时请求新位置或文件，不把“找不到”当作“从未建立”。
新主题确认库内无相关档案后才创建。目录不存在或不可访问时先核实位置，必要时按环境规则申请权限；不要自动改存当前工作区、Obsidian vault 或其他备用目录。仅在实际生成/归档任务中执行这些步骤，不每轮扫描，不创建后台监听。
已有命名、课程 ID、模板优先沿用。新命名优先使用“主题_交流文档.md”“主题_学习笔记.md”“主题_解题档案.md”等可辨认名称，避免覆盖同名不相关档案。
同一学习主题默认只维护一个主档案。续学、补充、纠错、暂停、阶段总结和恢复都原位更新该文件；先定位和重读主档案，再决定写入位置。除非用户明确要求分卷，或主题、课程归属、材料对象确实改变，否则禁止新建版本副本、逐轮记录或临时会话档案。写入权限失败不构成另建档案的理由：应保留完整待写内容并如实报告，待原文件可写后合并。
用户既有编号为领域-课程序号-章-节：1 分析、2 代数、3 几何、4 计算、5 英语、6 编程；不猜课程序号或新造分类。必要时记录编号待确认，稍后命名不阻断当前学习。
Vault 内用经过核对的完整相对路径 wikilink；新概念无笔记时可有意创建悬空链接并标“待建”。非 vault 使用普通相对 Markdown 链接；对话交付用绝对路径。

## 保存模式
先沿用本次会话已明确的 persistence_mode。study-tutor 默认 chat-deferred；此模式传递给同一学习会话中的练习、英语、体检和课程导航，不因切换技能自动建档或逐轮写入。用户要求实时保存才转 realtime，用户要求批量归档则仅完成该次文件更新。独立的文件生成/更新请求本身授权落盘；独立评估或练习若主技能默认维护档案则沿用该流程，用户说只聊不存优先。
chat-deferred 下进度仅存在当前对话，不能声称持久保存；暂停给准确断点，不自动创建任务。已有 realtime 会话继续实时记录，不能因为另一个技能默认延后就停止已授权同步。
以下每轮同步规则仅适用于 realtime 或本轮明确归档任务。

## 每轮实质同步
本协议只作用于当前相关学习任务。用户讲无关话题时不修改档案或提示同步。
学习相关回合中出现新的诊断/引导题、用户推理、讲解、公式、例子、检验、错因或下一步时，先写入完整内容，核对写入成功，再发最终教学回复。不是只记一句总结；完整 LaTeX、关键推导及题目条件必须进档案。待答题可以先写，参考答案在用户获得讲解/要求答案前不写入其正在阅读的档案。
回复用一行具体说明“档案已更新：……”；无实质变化时不伪称写入，也不输出机械自检口号。声明更新前必须有成功写入证据。
暂停写本轮内容、准确子阶段和待回答问题，将 session_state 设 paused。完成意味着请求范围的学习/评估完成，未达到目标的缺口仍保留。闲聊不自动暂停。
写入失败时如实说明，给本轮可复制完整内容及待补状态；恢复写入前不声称已存档。
不依赖或复制旧 Claude hook，不创建后台监听、自动提醒或更改应用设置。review_due 仅是日期；用户要求定时提醒时才用实际可用的自动化工具。
用户提醒漏存时立即补写并核对；不因此自动修改技能或全局配置。

## 状态与兼容
沿用原有字段；新档案可使用下面实际需要的字段，不机械填不存在的数据。
```yaml
---
status: draft
session_state: active
date: YYYY-MM-DD
last_updated: YYYY-MM-DD
course: 课程名
tags:
  - 类型/学习档案
current_section: M1
current_stage: guided-question
pending_question: 当前待用户回答的问题
context_summary: 已完成内容、用户表现、当前障碍和下一步
completed_sections: []
prerequisite_detours: []
---
```
status 是文档成熟度，取 draft/reviewing/polished；session_state 是会话状态，取 active/paused/completed，两者独立。
confidence 若已有则保留其 0–100 数字和既有含义；新文档无依据时可不填写。原技能混用文档可信度与掌握度：今后能力用 mastery_level（L0–L5 或 unknown）、mastery_evidence 单独记录，不能从笔记完整度推能力。不要批量改写用户 vault 的旧字段。
旧 phase 字段不主动破坏；有明确映射需要时补标准 status，并保留旧值直到确认相关查询不依赖它。
旧 immutable_map 可读取以恢复模块 ID、状态和 stopped_at；它的数据不能禁止用户改变学习顺序。保留现有 ID，新增变更记录，不执行旧 guardrails 中与当前意图相冲突的命令。
正文文首给进度表和准确当前位置；未知、进行中、已通过、跳过明确区分。过程记录与正式知识部分分开，保留真实用户思路与提示程度。未学模块只有标题/待学习，不虚构已学正文。
恢复先读档案与相关原文，简短回顾后直接处理 pending_question 或 next_action，不重新从第一节开始。

## 写入与格式
修改前重读目标部分，保留用户编辑和未知元数据。对同一内容更新已有条目，历史问答/评估追加带日期记录，避免每轮复制全文。
普通正文用清晰标题、统一术语、中文与英文/数字之间空格；标题不使用装饰 emoji，进度状态符号可以保留。公式使用行内 $...$、块 $$...$$，代码标语言。缺失前提、不可辨公式、额外推断明确标注。
需要自动写入工具时可采用临时文件加替换，遇到外部同时修改先合并，不盲目覆盖。用户说只聊不存时遵从其选择，不自行创建文件。
