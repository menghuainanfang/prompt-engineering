## 1. 角色、目标和工作方式

你是本项目的产品与工程协作者。请根据本任务书，完成 ReadingOS v0.1 的真实工程实现，提供用户可以在自己的电脑上启动、长期保存阅读资料并向朋友分发试用的版本。

先读取当前工作区适用的 AGENTS.md 和已有文档，检查是否已有 ReadingOS 项目及未提交修改。保护既有工作，不覆盖无关文件、不重置用户改动、不强推远端。若当前目录只是提示词仓库，为应用建立独立目录与 Git 仓库；不要把应用源码、书籍或本地数据库放入 prompt-engineering。

在开发前完成环境自检：操作系统、架构、Git、Node.js、包管理器、可用磁盘、网络、现有工程及远端、桌面构建工具。Windows 为首要目标，界面默认简体中文；其他电脑平台属于后续兼容方向。若考虑 Tauri，再检查 Rust、Windows C++ 构建工具和 WebView2；若使用 Electron，检查其运行与打包链。

给出简短执行计划并开始实施。常规可逆工程选择可自行决定并记录理由。只在真正缺少必要信息、涉及破坏既有数据或无权限的操作时询问。遇到环境阻塞，先完成不受阻的工作，准确报告阻塞及用户可执行的下一步，不把未完成内容标为完成。

## 2. 已确定的产品定位与边界

ReadingOS 长期可以成长为个人生活管理平台，未来容纳日程、日记、待办、作息、运动、饮食和饮水管理。当前集中实现阅读模块：启动直接进入书房，不建设空的生活综合首页，不提前开发插件平台。

阅读的重点是积累自己的认识和实践，而不只是打开文件。完整闭环为：

导入电子书或登记纸质书 → 阅读与批注 → 阅读日志 → 置顶总心得 → 提炼观点 → 尝试实践与复盘。

本版本本地优先、离线可用、单用户，无需注册和服务器。分享应用不等于分享个人资料；朋友安装后拥有独立书库。天气、网络励志语录、通用日历、日记、生活待办、健康管理、云同步、移动端、多人协作及正式 AI 功能不在 v0.1 范围。

P0/P1/P2 表示开发顺序。完成可靠的 P0 阅读流程后，在 v0.1 中加入精简版观点、实践、计划和统计；AI 为后续版本。若这些尚未完成，不可声称整个 v0.1 已验收。

## 4. 最小技术方案

优先评估 TypeScript + React + Vite + Electron + SQLite：统一前端生态，适合鼠标绘制、PDF.js/EPUB 集成以及 Windows 打包。若已有项目或环境证明 Tauri 更合适，可以采用 TypeScript 前端 + Tauri + SQLite，并在架构决策文档中说明。选择一种桌面框架，不并行建设两套。使用受支持且兼容的版本并提交锁文件；不要凭记忆写“最新版本”。

保持模块边界：library、reader、annotations、notes、insights/actions、plans/stats、storage、settings。ReaderAdapter 统一打开、定位、选区、批注和进度接口，PDF 与 EPUB 可各有一个内置实现。v0.1 设置允许指定各格式默认内置阅读器；只有一种实现时如实显示。外部系统阅读器可以是可选的“外部打开”，但无法保证内部批注和进度联动；不要承诺同步，也不必开发多引擎市场。

采用数据库存结构化数据、应用数据目录存受管理的原书与附件的方式。仅用 localStorage 保存全部书库或仅靠浏览器开发服务器，不满足最终交付要求。处理 SQLite 驱动与桌面打包的兼容性；若选 Electron 原生模块，验证 ABI/rebuild 以及安装包中的实际可用性。

安全要求贴合本地书籍导入：Electron 使用隔离的 preload 和明确 IPC 白名单，不向书籍内容暴露 Node/文件系统能力；Tauri 使用最小能力授权。禁用书籍脚本，限制远程资源，做好内容隔离、CSP 和链接处理。所有资源本地打包，不依赖 CDN 才能阅读。备份解压校验路径，防止路径穿越。首版不绕过 DRM、不执行导入文件中的脚本。

## 5. 书房和书籍主页

书房提供书籍卡片/列表、导入按钮、登记纸质书、按书名/作者/标签搜索与基本排序。每本书如一个独立资料夹，包含书名、作者、封面、格式/纸质类型、标签、阅读状态、进度及最近访问时间。元数据自动识别失败时可手动补齐。

点击书籍默认进入书籍主页。固定优先级为：

1. 总心得：置顶显示，有内容时无需先打开阅读器才能看见。
2. 继续阅读：电子书有按钮，纸质书提供手动进度，不出现空白阅读器。
3. 核心观点与实践行动。
4. 阅读日志：可按日期、章节筛选。
5. 批注与摘录：可定位回原文。

采用已经确认的 B 方案：“一篇可持续编辑的总心得 + 多篇可选阅读日志 + 观点卡片”。日志可按日期或章节添加；用户也可以只写长读后感，不强迫每次阅读写日志、生成卡片或使用固定模板。

编辑器选择容易维护的实现，至少支持标题、段落、列表、引用、基础文字颜色及自动保存，可采用 Markdown 数据配合工具栏与预览。明确显示保存中/已保存/失败；失败时保留内容并可重试。总心得与日志须支持导出和简单历史版本恢复，避免误覆盖长期心得。

## 6. 阅读、导入和格式范围

v0.1 必须支持 PDF 与 EPUB；纸质书不要求电子文件。TXT/Markdown 在低成本且不拖延核心时可加入，否则列入后续版本。MOBI/AZW3/FB2/CBZ 等属于逐步扩展；未实现格式明确提示，不显示虚假成功。不包含 DRM 解密、OCR 和复杂格式自动转换。

导入时复制原书至应用管理目录，记录文件哈希与原始名称，原文件保持不变；源文件随后移动或删除仍能阅读。重复文件可提示复用既有条目或登记另一阅读副本，不自动合并不同版本的书。失败应清理未完成导入并给出可理解的错误。

共同能力：目录（书中有时）、书签、进度保存与恢复、继续阅读、基本书内搜索（存在文本时）、键盘翻页/导航、侧栏展开收起。无目录、无文本或格式损坏都要有合理回退。

PDF 提供翻页、跳页、缩放、适宽，支持文本层选区。扫描 PDF 可阅读并使用区域高亮、鼠标绘制和坐标文字批注；无文本层时明确说明无法文字选择与搜索。PDF 不通过改写正文实现字体设置。

EPUB 提供字体族、字号、行距、正文颜色、背景/主题、翻页或滚动模式；文字高亮与键盘笔记。用 CFI/书内稳定定位加摘录上下文支持重排后的定位，不能把屏幕页码当永久地址。验证简体中文书籍、章节、图片和脚注/链接的基本表现。

## 7. 批注与鼠标手写交互

主要设备是普通鼠标，偶尔可能使用手写笔，目前没有指定笔型号。默认模式为阅读/选字。PDF 工具栏显式切换阅读、文字高亮、区域高亮、文字批注、画笔、橡皮/选择；Esc 返回阅读模式，避免普通拖动误画。

必须支持：

- 高亮多色与透明度；文字批注文字颜色；画笔颜色、粗细。
- 鼠标按下拖动绘制线条、圈注和简短手写，Pointer Events 与 pointer capture 处理拖出区域。
- 文本批注点击或选区打开输入框；完成后以标记和侧栏条目呈现，可编辑/删除。
- 笔画选择或整笔擦除，以及当前编辑会话的撤销/重做。
- 批注完成即保存，重启后恢复；工具状态与颜色有明确提示。
- 使用 pen 类型时可读取可用压力；无压力时使用固定宽度。没有真实设备验证就不能宣称笔适配已完成。

坐标以 PDF 固有页面坐标或可逆的规范化坐标保存，并处理 CropBox、旋转、缩放、滚动与 HiDPI；不得只存屏幕像素。文字选区高亮保存页码、矩形/quad 与摘录；自由绘制保存路径点与样式，不仅保存截图。原始 PDF 不被覆盖。

PDF.js 已有批注能力与自建层的复用先做小验证；记录选择与限制。数据库中的应用批注是可靠来源。v0.1 不要求把批注写回通用 PDF；支持结构化备份和笔记导出，清楚说明在外部 PDF 阅读器中不会自动出现。可加导出带批注 PDF，但不得挤占核心功能。

EPUB 只要求文字高亮和键盘批注；不加入跟随重排的手写画布。

## 8. 心得、日志、批注、观点与行动的联动

从批注条目提供“写入阅读日志/引用到总心得/提炼观点”。使用显式操作，不自动把每条批注塞进心得。保留原文摘录、书籍、位置、批注 ID 与用户解释，支持从笔记点击“回到原文”，并从批注看到引用它的记录。

链接应有稳定 ID；不要仅复制无法追溯的字符串。原批注删除后，心得保留引用快照和用户文字，并标注来源已删除；定位失效时显示状态和摘录，不错误跳转。更换原书版本创建新文件/版本身份，不悄悄将旧批注附到新文件。

观点卡片最小字段：标题、自己的理解、来源链接、标签、创建/修改时间。允许手动编辑与同书多个来源。实践行动最小字段：关联观点、具体做法、可选复盘日期、状态（待尝试/进行中/已完成/暂缓）、实际结果与反思；完成行动不自动代表观点“正确”。

标记读完时引导写总结并提炼至少一个可尝试的要点，但允许“稍后补充”完成状态变更。不通过强制表单破坏阅读体验。纸质书支持手动页码/章节/摘录，链接不指向不存在的电子页面。

## 9. 数据模型、保存与备份

设计并实现最小清晰模型，可调整表名但保留语义：

- Book：稳定 ID、类型（digital/paper）、书名/作者、标签、阅读状态。
- BookFile：格式、相对路径、哈希、文件/版本身份。
- ReadingProgress / Bookmark：按格式区分的定位与更新时间。
- Annotation：关联 BookFile、类型、定位、样式、摘录、文字/路径。
- BookSummary / ReadingLog / NoteRevision：总心得、日志与可恢复的笔记修订。
- Insight / SourceLink：观点及可追溯来源。
- Action / ActionReview：行动与实践结果。
- ReadingPlan / CompletionEvent：月年计划、读完/重读事件。
- SchemaVersion / Settings：迁移与设置。

使用迁移、外键/等效约束、事务和稳定 UUID；路径相对数据目录，位置结构可版本化。计划引用 Book，不重复创建书籍；多格式副本与心得的归属要清楚。

提供：

1. 每本书心得、日志、观点、行动及文字批注的 Markdown/JSON 导出；保留原文来源信息。手写路径在结构化导出中保存，不伪称可转换为文字。
2. 完整备份 ZIP：一致性的 SQLite 快照（正确处理 WAL）、原书、封面/附件、批注、设置、manifest 与 schemaVersion。排除秘密、缓存和临时文件。
3. 首版可只支持“恢复到新数据目录/空书库”，无须开发复杂合并。先校验版本、路径、引用和文件哈希，恢复成功后再切换；失败保留现有数据。升级前备份，未来版本备份不兼容时清晰拒绝。

确保关闭重启、安装升级和重复导入不会丢心得、批注和位置。至少进行一次真实“备份 → 新目录恢复 → 打开原书并检查链接”的演练。

## 10. 阅读计划与统计

实现简版年度目标、月度计划：年度可设计划读完数量；各月可选书目，书籍可跨月继续读。支持计划、在读、读完、暂停/放弃等状态，读完日期可修改，纸质书与电子书同等统计。

默认统计按完成日期落入的月份/年份计算去重书籍数；同书重读另记完成事件并单列重读次数，不能因多文件、跨月计划或多个日志重复计数。保留历史完成事件，不在开始重读时抹去上次读完记录。清晰显示计划数量、实际读完数量与在读书目，无须复杂排行榜或未经验证的阅读时长估算。

## 11. 后续迭代与 AI 记忆方向

在 docs/ROADMAP.md 中列出，当前仅预留稳定数据基础：

- v0.2：阅读器体验、更多格式、搜索、反馈修复、可靠批注导出。
- 后续 AI：用户主动选择资料，辅助提炼观点、汇总个人心得、发现跨书联系；提供商可配置，未配置时基本应用完整可用。
- AI 的长期记忆来源为用户认可的观点与实践复盘，记录来源、创建时间、修订、是否由 AI 提议、是否用户确认、归档/删除状态；思想变化应可追溯。不要把模型生成的摘要直接当用户信念。
- 不在 v0.1 引入向量数据库、云端全书上传或伪造“记忆已接入”功能。未来外发须明确展示发送内容，密钥独立安全保存，不放在书库备份、日志或 Git。
- 更后续：待办、日记、天气、习惯、健康等模块可引用行动 ID；不提前建设全套生活管理。

## 12. 实施顺序、验收与交付

按可运行的纵向切片推进，每阶段提交有意义的 Git commit：

1. 环境与参考项目核验；短架构决策、依赖许可清单；桌面空壳与持久化。
2. 书架、电子导入、纸质书、主页与总心得/日志自动保存。
3. PDF 阅读与鼠标批注；EPUB 阅读、文字批注与可靠定位。
4. 双向来源引用、观点、实践行动、精简月年计划和统计。
5. 导出/备份/恢复、错误处理、UI 打磨和 Windows 打包验收。

必须进行与风险相称的验证：类型检查、lint（项目配置时）、生产构建；数据/迁移/备份完整性、坐标变换、EPUB 定位与计数逻辑的针对性测试；至少一条实际端到端读书流程。使用自己生成或可公开再分发的测试资料，不能把用户的付费书、私人笔记或受限全文提交 GitHub。

验收清单：

- [ ] 在 Windows 桌面启动；联网安装依赖后，断网仍能打开书、批注和写心得。
