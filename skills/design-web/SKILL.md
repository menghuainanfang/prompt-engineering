# 网页设计与验收

已有项目先读局部规范、组件和设计系统，保持实际产品语境。新页面根据受众、内容和主要动作制定简短视觉方向，颜色、字体层级、布局和一个特色元素服务内容，不捏造“用户已拒绝多版设计”的历史。
设计上的具体偏好遵从用户，不把紫色、居中、某字体等列作普遍禁用。信息编号必须表示真实顺序，文案说用户能做的事，空状态/错误给明确下一步。
简单独立演示可用单文件 HTML；只有项目/需求确需状态、路由和复用组件才选择框架。尊重现有栈，不因旧技能硬套 React 18、特定 Tailwind/Vite 版本或安装几十个组件。
使用当前可用工具和运行时；本机可通过 workspace dependencies 定位 Node/浏览器库。脚本路径与命令适应宿主 shell，不假定 Bash、/mnt/data 或旧平台专用产物接口。

## 实现与验收
新建或修改后检查页面实际行为：关键按钮、表单、导航、加载/错误/空状态；依项目需要运行现有检查。仅测试请求不擅自重设计。
浏览器测试先确认目标地址和已运行服务，检查渲染 DOM 后用可访问 role/name 等定位。等实际可见元素/应用就绪，不统一等待 networkidle（长连接应用可能永不空闲）。
检查桌面与窄屏溢出、键盘焦点、文本可读性和 reduced-motion。查看截图以验证布局，不能只依赖 HTML 源码推断视觉效果。
已有服务不随意停止，只清理本次启动的进程。运行工具缺失时区分静态检查与实际浏览器验证，说明未测部分。
按用户要求交付仓库修改或独立页面；单 HTML 仅在需要离线/便携时打包，并验证资源不依赖未声明网络。不能把未实现操作伪装成可用产品动作。
