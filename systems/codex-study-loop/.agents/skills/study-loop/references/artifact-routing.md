# 产物流转

## 事实源

| 内容 | 唯一事实源 | 其他位置只保留什么 |
|---|---|---|
| 教学过程、用户原始推理、提示记录 | 用户配置的学习主档案目录中的主题主档案 | Obsidian 只保留精炼结论和指向主档案的普通路径链接 |
| 课程依赖、据点状态、通关证据 | 课程地图 | 笔记只引用相关据点 ID |
| 稳定定义、定理、方法、知识联系 | Obsidian 学科目录 | 主档案保留学习过程，不另造第二份长期知识正文 |
| 题目、解法尝试、错因、提示程度 | 解题档案/习题笔记 | 长期笔记只吸收可迁移方法 |
| 待制卡内容 | 用户配置的 `Anki卡片候选.tsv` | 笔记可标记“已提出候选”，不复制队列 |
| 已导入卡片、间隔、Again/Hard | Anki | 周复盘只记录需要行动的模式 |

## Anki 候选队列

TSV 列为：

`Status`, `Front`, `Back`, `Tags`, `Deck`, `Source`

- `Status` 使用 `候选`、`通过`、`已导入` 或 `暂缓`。
- `Front` 是 Anki 判重的第一字段；已经导入后应保持稳定，修改答案而不是随意改问题。
- `Tags` 用空格分隔，推荐 `学科::课程`、`主题::概念`、`来源::错题` 这种层级标签。
- `Deck` 留空时导出脚本使用 `学习闭环`。
- `Source` 写可追溯的笔记路径、教材章节或题号，不写聊天寒暄。

运行：

```powershell
.\scripts\prepare-anki-import.ps1 -Inbox "<Anki卡片候选.tsv>"
```

脚本只导出 `通过` 行，并保留原候选文件。用户在 Anki 的“文件 → 导入”中检查预览；确认成功后再把对应行改成 `已导入`。

## 周复盘

使用 Obsidian 的 `90-系统/04-学习闭环/周复盘模板.md`。只处理会改变下一周行动的信号：新获得的独立/迁移证据、重复错因、Again/Hard 集中点、失效卡片和需要调整的课程路线。不用完成数量代替掌握证据。
