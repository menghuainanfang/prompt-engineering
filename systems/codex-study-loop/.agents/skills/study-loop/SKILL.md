# 学习闭环

把现有工具作为互补层使用，不复制同一份正文：

- 当前对话负责即时教学与推理；沿用既有 `persistence_mode`，默认不因每轮回答写文件。
- 用户配置的学习主档案目录保存完整学习档案、课程地图、练习证据和评估报告。
- 用户配置的 Obsidian vault 保存精炼后的长期知识、索引、周复盘和 Anki 候选；不复制完整聊天或解题档案。
- Anki 是已导入卡片的复习时间与记忆表现事实源。卡片进入 Anki 后，不再用 Markdown 的 `review_due` 模拟同一套调度。

需要写文件或制作卡片时读取 [产物流转](references/artifact-routing.md)。需要判断卡片质量时读取 [卡片准入](references/card-quality.md)。

## 路由

根据当前目标调用最窄的现有技能：课程级规划用 `study-roadmap`，渐进教学用 `study-tutor`，逐题训练用 `study-practice`，能力实测用 `study-assessment`，笔记整理用 `study-notes`，论文总览用 `study-paper-brief`，英语训练用 `study-english`。不要把本技能变成这些技能的重复实现。

完整闭环遵循：明确目标与通关证据 → 教学 → 无提示检验或练习 → 基于证据判定 → 精炼知识 → 筛选卡片 → Anki 复习反馈回流。用户只要求其中一段时只完成该段，不强迫跑完整流程。

## 掌握状态

能力状态只依据可观察证据，不由笔记长度、看过答案或卡片数量推断：

- `unknown`：未测。
- `learning`：已接触，但尚无独立表现。
- `guided`：经提示可完成。
- `independent`：无提示完成同类任务或准确解释。
- `transfer-ready`：能处理变式、反例、条件变化或跨情境应用。

将证据写成具体行为，例如“独立说明一致收敛与逐点收敛的量词次序差异”，不要只写分数。课程地图只吸收稳定的状态变化；逐题过程留在练习档案。

## 阶段收尾

自然结束一个主题或用户要求收尾时，给出紧凑交接包：已达到的证据、仍薄弱的点、应更新的长期笔记、Anki 候选及下一步。遵守当前保存模式；没有写入工具或授权时只在聊天中交付，不声称已归档。

卡片先进入候选，不把整段讲义批量制卡。仅当问题可独立理解、答案稳定、确实值得长期提取且已核对时标记为“通过”。使用本系统的 `scripts/prepare-anki-import.ps1` 生成导入文件；脚本不直接修改 Anki 数据库。

## 复习回流

用户带回 Anki 的 Again/Hard 卡片时，先区分：概念模型错误、条件遗漏、检索线索差、卡片过大或单纯熟练度不足。概念错误回到 `study-tutor`，方法与迁移不足回到 `study-practice`，关键前置不明时用 `study-assessment`。修正知识或卡片后再交回 Anki；不要仅靠重复次数掩盖坏卡片。
