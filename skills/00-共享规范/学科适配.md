> 各技能主体不再内嵌学科表格，需要时读取本文件。
> 最后更新：2026-08-16（合并自 AI辅助学习 v1.0 与 渐进式交互学习 v1.1，消除重复）

## 识别规则

1. **需求澄清时自动执行**：提取用户问题中的关键词，匹配到学科大类。
2. **匹配优先级**：用户明确说的 > 关键词匹配 > 默认数理（中性概念按数理处理，因为数理模板最"正式"）。
3. **跨学科概念**（如"信息熵"出现在物理/CS/统计中）：根据上下文和用户背景判断；若不确定，用一句话确认（"你是从热力学角度还是信息论角度学熵？"）。
4. **不确定时**：如果关键词匹配到多个学科且上下文不明确，自然地问一句确认。

|------|---------|---------|---------|---------|---------|
| **讲解** | 定义→定理→证明→性质 | 概念→行为→边界→最佳实践 | 规则→例外→语境→对比 | 背景→事件→因果→争议 | 问题→主张→论证→反驳 |

## 讲解模板（按学科）

**数理类**：`定义→定理→推导→性质`
- 精确给出数学定义和符号
- 定理/公式的条件与结论分开陈述
- 关键推导步骤（不省略跳跃）
- 从定义能推出什么重要性质
- 示例框架：「严格来说，{概念}定义为……这个定义有两个关键条件：①...②...。由此可以证明：……」

**编程类**：`概念→行为/语义→边界/陷阱→最佳实践`
- 这个概念对应代码中的什么？（类、函数、关键字、模式？）
- 它做什么、不做什么（语义，不只是语法）
- 什么情况下失效/不适用（时间复杂度退化、线程不安全、内存泄漏风险）
- 业界通常怎么用（idiom / best practice / anti-pattern）
- 示例框架：「{概念}在代码层面就是……它的核心行为是……但要注意，当{边界条件}时它会……所以实践中通常……」

**语言类**：`规则→结构→例外→语境/语感`
- 基本规则是什么（形式/结构）
- 典型用法和句型模板
- 例外情况（什么时候规则不适用）
- 母语者实际上怎么用（语境/语域/语感）
- 示例框架：「{语法规则}的基本形式是……比如你可以说……但要注意，当{语境}时这个规则不适用——母语者在这种情况下会说……」

**历史类**：`背景→事件序列→多方视角→因果分析→史学争议`
- 什么背景/条件导致了事件发生（长期/短期原因）
- 事件的关键时间节点和转折
- 不同参与方的视角和动机
- 直接后果与长期影响
- 史学家对此有哪些不同解释（如有）
- 示例框架：「{事件}发生在{背景}下。关键转折是……从 A 的角度看……但从 B 的角度……。这件事的直接后果是……长远来看它改变了……关于其原因，史学界主要有两种解释：……」

**哲学类**：`问题意识→核心主张→论证结构→反驳与回应→当代关联`
- 这个概念要回答什么问题（为什么它是重要的哲学问题）
- 核心主张是什么（一句话概括立场）
- 哲学家怎么论证的（论证结构，不是简单重复主张）
- 主要反驳是什么、哲学家如何回应（或可能如何回应）
- 这个概念在当代讨论中还在以什么形式出现
- 示例框架：「{概念}试图回答的问题是……它主张……论证的关键一步是……。反对者会说……对此可能的回应是……。今天关于{当代议题}的讨论本质上就是在问同样的问题。」

## 例子选择（按学科）

**数理类**：
1. **能用具体数字手算的例子**（如 2×2 矩阵、3 个节点、4 等分区间）
2. **可逐步骤演示的例子**（每一步的逻辑都清晰可见）
3. **有几何/物理直观的例子**（如果能画出来就更好）
4. **反例**（违反某个条件会导致什么结果）

**编程类**：
1. **最小可运行代码片段**（< 20 行，能直接跑出结果）
2. **输入→输出对照**（同一个函数对不同的输入产生什么输出）
3. **错误/边界示例**（什么输入会崩溃/返回错误/性能退化）
4. **重构对比**（同样功能，不用这个概念 vs 用这个概念，代码差异在哪）

**语言类**：
1. **典型例句**（清晰展示规则的标准用法，2-3 句）
2. **对比例句**（正确 vs 错误用法并排，差异一目了然）
3. **语境变异**（同一规则在不同语境下的表现——正式/口语/书面）
4. **母语者实际用法**（语法书写的和实际说的有什么差别）

**历史类**：
1. **一手史料片段**（引文、数据、当时记载，而非后人总结）
2. **时间轴/因果链**（事件不是孤立的——展示前后关联）
3. **多方视角还原**（同一事件，A 方的记载 vs B 方的记载）
4. **"如果……会怎样"的反事实推演**（帮助理解某个因素的因果权重）

**哲学类**：
1. **思想实验/场景构造**（"假设……那么……"——激活直觉）
2. **论证重构**（把原文松散论述重组为标准论证格式：前提1、前提2、结论）
3. **反例/两难**（挑战该主张的经典反例或两难困境）
4. **当代案例映射**（这个概念在今天的什么讨论中再现——AI伦理、自由意志与神经科学等）

## 例子呈现格式（按学科）

所有学科通用外层结构：`问题/设定 → 逐步展开 → 结果 → 关键启示`

**数理类**：
```
### 例N：{一句话描述}
**问题**：{具体设定，所有数字明确写出}
**逐步演示**：
第1步：{做什么 + 为什么这样做} → 得到：{中间结果}
第2步：...
**结果**：{最终结果 + 与理论对照}
**关键启示**：{这个例子说明了什么}
```

**编程类**：
```
### 例N：{一句话描述}
**场景**：{要解决什么问题}
**代码**：
```lang
{完整可运行的最小代码}
```
**运行结果**：{输出/行为}
**解读**：{代码中哪些行体现了概念的核心——逐行/逐块解释}
**变体/反例**：{如果去掉/改掉关键部分会怎样}
```

**语言类**：
```
### 例N：{一句话描述语境}
**正确用法**：
> {例句1}
> {例句2}

**对比（如果混淆）**：
> ❌ {错误例句} — 为什么错：{一句话}
> ✅ {正确例句}

**语境提示**：{什么情况下用这个规则，什么情况下不用}
```

**历史类**：
```
### 例N：{事件/现象名称}（{时间}）
**背景**：{之前发生了什么导致这件事}
**关键节点**：
- {时间1}：{事件1} — 意义：{为什么这个转折重要}
- {时间2}：{事件2} — 意义：...
**多方视角**：
- A 方视角：{他们看到了什么、动机是什么}
- B 方视角：...
**后果**：{直接后果 → 长期影响}
**启示**：{这个例子对我们理解该概念的帮助}
```

**哲学类**：
```
### 例N：{思想实验/论证名称}
**设定**：{假设的场景，所有细节}
**直觉反应**：{大多数人第一反应会怎么判断——为什么会有这个直觉}
**哲学分析**：{这个直觉背后预设了什么？哪些预设是可疑的？}
**启示**：{这个例子如何支持/削弱该哲学主张}
```

## 习题设计（按学科三级递进）

按三级难度出 3-5 道题。所有学科共享 Bloom 递进原则，但具体题型不同。

**数理类**：

| 级别 | 类型 | 考查目标 | 数量 |
|------|------|---------|:---:|
| **基础概念** | 判断/填空/选择/简答 | 是否理解核心定义和性质 | 1-2 |
| **计算应用** | 手算/推导题 | 是否能运用方法解决具体问题 | 1-2 |
| **分析解释** | 开放题/判断分析题 | 是否能解释"为什么"、判断边界情况 | 1 |

**编程类**：

| 级别 | 类型 | 考查目标 | 数量 |
|------|------|---------|:---:|
| **基础概念** | 选择/填空/判断 | 是否理解概念的含义和行为 | 1-2 |
| **编码应用** | 写代码/改代码/补全代码 | 是否能用这个概念解决具体问题 | 1-2 |
| **分析设计** | 开放题（"这个场景下用 X 还是 Y？为什么？"） | 是否能判断适用场景和权衡 | 1 |

**语言类**：

| 级别 | 类型 | 考查目标 | 数量 |
|------|------|---------|:---:|
| **基础识别** | 填空/选择（识别正确形式） | 是否掌握了基本规则和结构 | 1-2 |
| **主动产出** | 造句/改写（按给定语境写出正确句子） | 是否能主动正确使用 | 1-2 |
| **语境判断** | 改错/语境选择题 | 是否理解规则的边界和例外 | 1 |

**历史类**：

| 级别 | 类型 | 考查目标 | 数量 |
|------|------|---------|:---:|
| **基础事实** | 简答/填空（关键时间、人物、事件） | 是否理清了基本事实框架 | 1-2 |
| **因果分析** | 论述题（"为什么 X 导致了 Y？"） | 是否能建立因果链而非罗列事实 | 1-2 |
| **多方视角** | 分析题（"如果从 B 的立场看，结论会有什么不同？"） | 是否能超越单一叙事 | 1 |

**哲学类**：

| 级别 | 类型 | 考查目标 | 数量 |
|------|------|---------|:---:|
| **基础理解** | 用自己的话复述论证 | 是否真正理解了论证结构 | 1 |
| **论证分析** | 找前提/找漏洞 | 是否能拆解论证而非只记结论 | 1-2 |
| **立场思辨** | 构造反驳/提出反例 | 是否能独立进行哲学思考 | 1 |

**出题原则（通用 + 学科特化）**：
- 概念题要有区分度：选项/判断点要触及常见误解
- 每道题标注「如果卡住了，可以找我要提示」
- 数字/数据要"凑好"（用户应聚焦在方法，而非繁琐算术）
- 数理：计算题结果尽量为整数或简洁分数
- 编程：代码题明确写出函数签名和预期输入输出
- 语言：句子来源尽量真实（母语者会说的），不要编造不自然的例句
- 历史：分析题提供具体史料片段作为分析素材，不要让用户凭空回忆
- 哲学：思辨题给出明确立场（"假设你持 X 立场"），让用户进入角色

## 文科习题：讨论式原则（2026-08-17 用户反馈新增）

> **语言 / 历史 / 哲学（文科）的习题不以"纯做题"形式出现，而是以"讨论"形式出现。**
> 文科理解没有唯一标准答案——检验理解的方式是阐释与对话，不是对错判定。

1. **出题形式**：给一段真实文本/史料/命题 + 一个开放讨论点（"你愿意怎么读？为什么？"），不设填空/改错式的标准答案题。
2. **三级递进保留，但改为讨论递进**：①讨论"这处 X 指什么"（识别）→ ②讨论"换一种读法会怎样 / 你会怎么写"（阐释与产出）→ ③讨论边界与判断依据（语境判断）。
3. **互动方式不变**：一题一题讨论，用户先讲想法，AI 再回应完善；阶段6 的反馈框架照常适用。
4. **数理 / 编程不受此条影响**：保留原题型（计算/代码），因为其理解有可检验的对错。

| 学科 | 首选实例形式 |

## 不适用边界

以下类型的技能/材料**超出学习技能范围**，即使触发词匹配也应告知用户，直接按需回答，不启动学习工作流：

- 纯肌肉记忆/身体技能（游泳、乐器指法、发音口型纠正）
- 需要实时视听反馈的技能（视唱练耳、口语发音纠正——AI 无法听你说）
- 纯工具操作教学（"教我用 Photoshop 抠图"——更适合直接截图演示）
- 纯操作类教程（软件安装、IDE 配置、按键操作）——更适合直接演示
- 纯参考类文档（API 手册、命令列表）——更适合直接查询
